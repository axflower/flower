本次用户要求默认帮写为 `Ctrl+Shift+1`、润色为 `Ctrl+Shift+2`，并改善润色

## 默认与旧设置兼容

- `WritingShortcuts::default()` 使用主键盘 1/2，修饰键精确为 Ctrl+Shift，
  不包含 Alt/Win，不注册全局热键。纯修饰组合和其它合法自定义组合仍受支持。
- `writing_shortcuts` 保存时增加 `version: 1`。模型仍只暴露 draft/polish 两个
  组合，版本由序列化层维护，不改变主窗口或输入回调的接口。
- 缺少快捷键字段或两个组合均缺省时使用新默认。旧无版本配置的完整
  `Ctrl+Alt` / `Ctrl+Space` 默认对在读取时迁入新默认，不自动写用户文件。
  旧仅保存 key 的 Ctrl+Shift+1/2 默认对与新默认一致。
- 其它旧自定义组合、只改其中一个的组合以及显式保存的关闭选项保留。
  迁移只匹配完整旧默认对，避免逐项迁移造成自定义冲突。
  新版显式保存带版本；用户之后主动选择旧组合仍可稳定回读，不反复迁移。
- “恢复默认”、帮助、CLI 及当前分发说明使用新默认；修改或迁移后重新切换
  Flower 载入快捷键快照。在线总开关保存后立即生效的既有规则不变。

## 内置编辑规范

把专业编辑方法写为随程序内嵌的润色任务规范，作为本次请求的系统指令使用。
不新增技能市场、运行时下载、外部工具、模型切换或第二次付费请求。
帮写任务的正文生成规则保持原样。

润色目标是提升读者实际理解与使用体验：明确中心、调整顺序、理顺逻辑、
补足已有意思中省略的衔接和指代、适度展开表达。不能将润色实现为只换同义词，
也不能为了显得不同或达到长度而增加事实、理由、数据、承诺或空话。
仅对原文能够直接支持的内容作表达层补充；缺失事实继续保持模糊程度。

保留三种已有风格及持久化枚举：

- **通顺**：自然、清晰、完整且有层次。简略材料可适度展开为完整句段，
  改善结构和表达密度；简短、明确的指令或回复保持合适篇幅。
- **正式**：在同样完整清晰的基础上采用得体、准确的书面语，避免堆砌套话，
  不强化措辞、确定性、义务或承诺。
- **简洁**：先保留全部关键含义，再去重、压缩冗余、组织层次，不强制扩写，
  不以省略条件、否定、主体或待确认事项换取字数。

指令包含少量固定、非用户的编辑示例，说明如何展开原有意思而不虚构事实；
示例事实不能移入当前输出。仅原文已完整自然且没有实质改善空间时才保留其表达，
不得把“原样返回”作为常规捷径。

输入仍仅为用户显式提供的 1–500 字材料和任务选项，输出最多 800 字。
Chat Completions 与 Responses 使用同一润色规范和相同 JSON 材料边界；
材料中的指令、角色声明或链接仍为待处理内容，不具备系统权限。
人名、日期、时间、数值、编号、型号、英文、emoji、条件、否定、
承诺程度和不确定性继续保持。

不增加流式重发、后台自动采样或未授权模型请求；不因提示词升级改变
取消、超时、私密拒绝、一次消费、安全写回及完整响应门禁。

## 验证与证据边界

针对快捷键验证默认、旧完整对迁移、自定义及新显式旧对回读、读取不写盘、
生产 OnTest/OnKeyDown 路由、精确修饰与 repeat/预编辑保护。
旧纯修饰手势用显式自定义 fixture 继续验证，不能依赖旧默认。

润色验证两协议/三风格和简繁均接入同一规范，材料 JSON 精确保留、
输出和请求预算不变、帮写不误用润色规范。用固定公开材料建立编辑评价样例，
分别核对事实保真、结构、清晰度、有效展开、风格及无空话。
构造请求和假传输通过不等于真实模型质量通过；不读取用户密钥、正文或
调用其付费 API。真实质量仅在实际模型评测执行后作相应结论。
