# Flower 0.5.0 独立帮写与就地润色

自定义模型API与双协议、连接身份及外发授权迁移以`custom-model-api.md`为准，
覆盖本文固定智谱及单一密钥的相应条款。

最新滚动绘制、来源控件精简、默认Ctrl+Shift+1/2及快捷键自定义、可选限流退避
以 `writing-reliability-and-shortcuts.md` 为准，替代本文相应旧Ctrl+1/2规则。

状态：用户明确要求拆分两种功能，并已选择“原文旁候选浮层（更稳妥）”。
本文件替代旧 `ai-writing-panel-0.5.0.md` 的界面、入口及润色流程约定；
旧文件第7节的12项文本质量样例继续作为语义验收，不复制或放宽金标。

## 1. 产品范围

- Ctrl+1 仅打开独立帮写窗口；不再提供帮写/润色双页签。
- 润色风格及输出字形预先在设置中配置；Ctrl+2 在安全选区旁显示候选浮层，
  使用配置发起本次润色，不打开独立润色工作窗口。
- 生成中和候选预览时，原选区正文保持原样，不建立临时替换或预编辑。
  只有用户点击“使用”才重核并替换；Enter、Space、数字键不采纳候选、不发送消息。
  关闭/取消及失败不写回；Esc 可在有效原输入上下文取消浮层。
- API 固定为智谱 GLM-4.7-Flash，用户自带模型标准 API 密钥。
  普通输入、简繁、离线纠错、短文本500/800字及不自动学习等边界不变。
- 未声明/私密/不支持范围不读正文、不隐式回退剪贴板；Ctrl+2 无安全非空选区时
  只提示重新选择，不回退帮写或手动润色窗口。

## 2. 帮写窗口与视觉规范

- 独立标题“AI 帮写”，辅助标识“智谱 GLM-4.7-Flash · 在线处理”；
  右上“使用帮助”打开本地可滚动步骤，不自动打开浏览器、不请求模型。
- 温暖浅灰背景、白色卡片、清晰边框与留白；沿用设置界面原生主题语言，
  主按钮用统一强调色，次按钮低对比边框，危险/失败状态不用仅颜色区分。
  正文字体 Microsoft YaHei UI，标题/分组/提示分层，正常正文约14逻辑像素；
  8/12/16/24逻辑像素间距，小工作区优先自适应宽度和纵向滚动，不横向堆大控件。
- 上部卡片填要点，紧凑排列语气、长度、字形；下部卡片显示结果，
  无结果给简短占位；生成/停止按钮、状态和字数明确区分。
- 密钥设置折叠为连接配置区或通过明确按钮展开，避免长期占据主操作区；
  允许在设置中管理同一密钥，不显示/读取已保存密钥明文。
- 保留结果编辑、重生成失败保留上次完整结果、明确恢复原任务、复制及安全插入。
  恢复旧任务不恢复已解除的目标权限，也不重置已消费的应用资格。
- Tab/Shift+Tab、Ctrl+Enter生成、Esc先停止否则关闭；支持DPI变化、窄工作区，
  禁止关闭时向宿主PostQuitMessage，所有网络任务取消并join后释放窗口生命周期。

## 3. 设置与授权

`Settings.online_polish` 为向后兼容的配置对象：

- `enabled: bool`，缺省false；设置中勾选“允许按Ctrl+2将所选文本发送至智谱润色”
  并保存，表示用户了解文本外发、供应商处理条款及可能计额。
  Ctrl+2 每次都是用户明确的单次发送操作，不自动监听/上传选区。
- `style: PolishStyle`，`fluent`（通顺，缺省）、`formal`（正式）、`concise`（简洁）。
- `script: Option<ChineseScript>`，缺省None跟随当前Flower字形，可指定简体或通用繁体。

设置页通过“在线AI设置”入口配置上述参数和同一Windows受保护密钥；
保存/删除密钥和设置均不触发网络。设置只改变在线润色，不改变离线纠错开关。
保持现有激活快照规则：保存后重新切换Flower使输入法侧读取新参数，说明中明确提示。
主设置表单后续保存不得把刚修改的在线参数覆盖回旧值。

## 4. 润色浮层与任务生命周期

1. 用户先配置并启用在线润色，在宿主主动选择1–500字，按Ctrl+2。
2. 有未结束组词只提示先完成/取消，完整保留raw/caret/confirmed。
3. 在所属TSF线程的只读编辑会话内，先检查严格scope和非只读状态，
   仅捕获该选区、原文、规范context身份、原焦点窗口和激活身份；
   建立文本编辑观察器及单次写回授权，捕获选区附近屏幕矩形供定位。
   无可靠授权不发送请求，不为了预览降低选区检查。
4. 浮层使用WS_EX_NOACTIVATE/TOOLWINDOW，不取得键盘焦点、不切换原宿主，
   位于选区/光标旁并限制在工作区，长结果内部可滚动。
   状态为连接/生成/已完成/失败/目标失效，生成中“使用”禁用。
5. 后台任务只接收固定本次原文及配置，不持COM或HWND。
   完整结果才允许点击“使用”；不解释或执行模型文本，不自动发送/提交表单。
6. 使用时不恢复或抢占别的窗口焦点。必须仍是原前台窗口/输入焦点/context，
   激活、原选区端点/style、原文、可编辑性及观察器资格均有效。
   同步写会话再次核验后只对捕获range执行一次SetText。
   消费应用资格后即使写失败也不重试、不回滚，防止部分写入后的重复替换。
7. 原文/选区改变后即使改回，授权仍永久失效；切走/目标关闭/停用/新激活也不写回。
   浮层可显示失败或失效状态，使用按钮禁用；关闭取消并拒绝晚结果。
8. 同一激活只有一个主动写作任务。重复keydown只吃键；浮层存在时复用，
   不因重复快捷键自动重发/改绑。帮写与润色间切换须先结束/关闭现有任务，
   不在后台静默并发。每次重新发起必须显式操作。

## 5. 技术接口与不变安全边界

- 保留`writing`后台、固定HTTPS/模型、关闭thinking、90秒总预算、10秒连接、
  30秒收发、有界SSE及错误脱敏；不修改既有生成服务协议/额度策略。
- 帮写仍由`writing_ui::open_panel`承载，但只接受Task::Draft，
  Task::Polish不能再创建工作窗口；`--polish`独立手动窗口入口撤销。
- 新`polish_ui`只承载非激活候选浮层：
  `open_popup(request, anchor: RECT, apply: ApplyCallback, validate: Box<dyn Fn() -> bool>)`；
  返回`PolishPopup`，提供`close/is_open/hwnd/show`，Drop取消并join。
  `validate`仅在所属线程调用，调用前释放UI借用；网络线程不接触该回调。
- 生成前及后台结果展示/使用前检查资格；失效时取消并禁用使用，不能单凭
  控件是否可点击代替真实写会话校验。回调执行不跨RefCell可变借用。
- 帮写仍使用原独立窗口焦点恢复规则，润色则使用原焦点保持规则；
  两条路径分别实现，不通过放宽旧帮写foreground门禁实现浮层。
- 新设置对象采用serde缺省值，旧设置文件不自动启用外发；不增加key明文字段。
  凭据仍使用当前用户Credential Manager，不要求用户在聊天中提供key。

## 7. 最小充分验收与已知限制

- 设置：旧文件缺省不启用、风格/字形往返、保存普通设置不重置在线参数、
  密钥操作不发送、坏设置拒绝，不读取真实用户存储。
- 帮写：无润色页签/参数、帮助可打开可滚动、紧凑/高DPI截图、键盘导航、
  原结果身份/撤销权限/一次性及取消清理回归。
- 浮层：原文生成前后不变、未完成不能使用、坏目标/改回/跨context/晚结果拒绝、
  单任务/重复、非激活样式与原焦点保持；真实写会话只改原选区一次。
- 只使用假传输、合成样例和自有窗口/隔离TSF夹具；不调用真实API、
  不访问现存凭据、不注全局键、不安装/注册或覆盖旧dist。
- 旧版本前台往返夹具在当前环境被系统拒绝取得前台；本轮不重复无变化失败，
  不把绕过foreground校验的测试当桌面验收。真实宿主/真实模型质量和时延仍待
  可用的交互环境与显式测试凭据验证，未覆盖项必须随交付说明。
