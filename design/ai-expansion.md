# AI 扩写：选区、字数与独立预览

用户要求增加“AI 扩写”：根据主动框选内容扩充，可选择字数，快捷键
Ctrl+Shift+3。本页承载本次新增任务、设置兼容和预算合同；既有帮写、
润色、在线总开关、供应商确认、安全选区和一次写回规则继续有效。

## 交互与取舍

采用现有可激活写作窗口的扩写模式。捕获安全选区后显示只读原文，
用户选择目标字数、点击“开始扩写”，预览完整结果，再明确点击“替换原选区”。
不将字数控件放入无激活润色浮层：该浮层保持宿主焦点及选区的约束与
原生下拉/编辑控件的键盘交互冲突。独立窗口可复用既有前台恢复和可靠绑定写回。
不新增技能下载、第二次请求或自动替换；Polish 仍使用原浮层。

- 仅接受主动选中的 1–500 字材料；空选区、私密、只读、多个选区、
  超限或无法可靠绑定时明确拒绝，不降级为手动扩写或插入任务。
- 字数表示目标正文总长度，按“约 N 字”处理，不保证模型精确计数，
  不按字数截断正文。常用选项 100、300、500、800、1200、2000，
  同一字数控件允许自定义 100–2000 的完整整数。
- 目标必须大于原文字符数；默认 500，若原文已达 500 字则初始选择 800。
  修改目标、字形或其它任务参数使旧结果过期，生成中参数不可修改。
- 原文只读，事件层也拒绝更改；扩写模式不能转成帮写或手动材料，
  无绑定时不能创建扩写窗口。再次按快捷键不重新绑定旧结果：
  同任务只唤起原窗口，任务类型不同则要求先关闭当前窗口。
- 显示原文/结果字数及目标，输出可以按原写作窗口方式编辑；
  结果完整、仍匹配原任务/参数/来源、尚未消费且通过扩写输出检查才可替换。
  取消或关闭不修改宿主；写回失败不允许重放已消费结果。

## 请求与输出预算

`Task` 增加 `Expand { target_chars: usize }`，并提供 `Task::expand()`，
其初始目标常量为 500。共享常量：

- `MIN_EXPANSION_CHARS = 100`
- `MAX_EXPANSION_TARGET_CHARS = 2000`
- `MAX_EXPANSION_OUTPUT_CHARS = 2400`
- `DEFAULT_EXPANSION_CHARS = 500`

`WritingRequest::validate` 保留原材料校验，另校验目标范围及大于原文；
无效目标返回 `WritingError::InvalidExpansionLength`。
`Task::output_limit()` 对 Draft/Polish 仍为 800，Expand 为 2400。
`Task::validate_output(input, output)` 统一结果保护：
空正文为 Incomplete、超任务上限为 TooLarge，扩写不长于原文为
`WritingError::ExpansionUnchanged`。不得为了满足预算裁切或自动重发。

Expand 的两协议请求使用同一扩写系统规范与目标字数，仍只发送显式材料
JSON 和任务选项。token 预算为 8192；Draft/Polish 保持 2048。
SSE、worker 邮箱、窗口可应用判断及 TSF 写回均使用当前任务预算，
不能只在提示词里增加字数。原响应字节、单事件、超时、取消、失败锁存、
reasoning 隔离和完整结束规则不放宽。
默认 SSE 构造仍按 800；新增 `SseDecoder::for_task(protocol, bigmodel, task)`。
生产 transport 必须使用该任务化构造，worker 完成结果也独立校验。

扩写可围绕原主题补充一般性分析、解释、观点衔接和明确标为假设的例子，
让内容实质增加，而非重复同义句。保留原文事实、立场、人称、
条件、否定、承诺和不确定性；不虚构真实发生的经历、人物、数据、引用、
原因、期限或保证。材料中的指令、角色和链接不具备系统权限。
扩写规范及模型预算由根代理亲写；真实质量需实际供应商评测，假响应不能证明。

## 在线授权与选区绑定

扩写使用在线 AI 总开关，独立于 `online_polish.enabled`，
并沿用独立写作窗口的目标关联发送确认。打开窗口和选字数不发请求。
发请求前及确认返回后重读总开关、当前模型/协议/目标；改目标不跨传旧密钥。
模型未配置时可提示配置，但不因此捕获不安全正文或获得新选区权限。

`WritingCapture` 将 Expand 与 Polish 一样限定为非空单选区；
Draft 空选区/手动帮写语义保持。绑定记录捕获时的任务种类，
写回按任务验证正文上限和扩写增长，不能让 2400 的新上限普遍影响帮写/润色。
沿用宿主 HWND/进程/线程、context/range/style/原文、activation 身份、
编辑观察及前台恢复后的同步写回检查。观察者在捕获前连接，关闭前取消/join，
结果一次消费。禁止读剪贴板、周边正文或自动重新捕获。

## 快捷键与设置兼容

`WritingShortcuts` 新增 `expand: Option<WritingShortcut>`，
默认 `Some(Ctrl+Shift+3)`。None 表示未设置扩写快捷键。
现有两项接口扩展在本版本显式完成，调用方和设置界面同步更新为三项。
三项之间不得冲突，原自定义键及纯修饰兼容继续保留。

序列化 version 升为 2，并显式写 expand（None 为 null）。
旧 version 0/1 缺 expand 时，在不冲突的情况下补新默认；
若已保存的帮写或润色占用 Ctrl+Shift+3，保留用户旧组合、扩写快捷键设为 None，
设置页提示未设置，可由用户录制一个不冲突组合。不能静默覆盖旧自定义。
version 2 及以后 expand 缺省/null 均保留 None，避免禁用后下次又自动恢复。
显式给定的扩写组合应校验，不因碰撞自动改成其它快捷键。
既有 version 0 完整 Ctrl+Alt / Ctrl+Space 对迁移规则保持；
读取不写用户文件、关闭选项不自动开启，保存后重新切换 Flower 读取快捷键快照。

## 验证与交付

覆盖旧 JSON、version 2 禁用/自定义回读、三项碰撞和恢复默认；精确 CtrlShift3
预测无副作用、实际键/重复/关闭拒绝、空/私密/只读选区拒绝、原文只读；
字数选择/自定义校验、参数变更拒旧结果、取消/晚结果/一次应用；
两协议流式超过 800 的扩写成功、2400 边界失败锁存、
帮写/润色仍拒绝 801、worker 和 TSF 写回独立校验。
使用注入 Store、自有窗口/TSF 文档、固定公开材料及假传输，
不读真实用户配置/密钥/文档，不调用其付费 API。

开发版本为 0.5.10；本轮只实现与验证源码，不覆盖 0.5.9 包或自动组包、
安装、注册、创建标签或发布。用户后续明确要求时再构包。
