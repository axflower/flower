# 保留即时首键的紧凑词典索引

## 目标与基线

用户要求在保证全部功能与性能的前提下大幅缩小安装器和 ZIP。
0.5.7 的 ZIP 为 282,245,884 字节，安装器为 213,744,496 字节。
其中 DLL/settings 各嵌入同一 280,859,706 字节索引，两个 PE 在 ZIP 中
合计压缩占用 188,086,483 字节，占 66.6%；固定模型约占 59.5 MB。

本合同补充 `instant-first-input.md`。保留全部 1,754,389 个拼音 key、
2,088,650 条词条、原权重/常用分类/规范读音、查询顺序与统一预算。
模型、runtime、词典来源审计、许可和完全离线安装继续保留。
不恢复首键全量解压/解析/建表，不改变模型精度或候选质量。

## 方案选择

仅共享字符串和连续 ID 区间的原索引探针约减少 19.1 MB deflate，
两个副本约减少 38.2 MB，仍不足以充分解决问题。
外置共享索引会引入新的运行期文件加载、信任及生命周期契约，
本轮优先保留二进制内嵌与安全 Rust 的只读随机访问。

采用版本 2 紧凑表示：

- 保持显式 magic/version、固定大小 header 和 LE 整数、有界读写，
  header 打开仅检查固定数量描述符/范围，不遍历整表或分配基础索引。
- 大型 metadata 按字段分列，避免把偏移、长度、权重、计数混排到每条记录。
  entry 的 text/reading 定位和 weight 分列；everyday 使用紧凑 byte 或位图。
  完整 text 数据按词条顺序保存；reading 按首次出现共享。
  两种 key 的 offset/length 和 word 引用各自分列，所有 key/字符串保留原文。
- ID 引用支持连续区间与显式 ID 数组。连续区间逐项直接算 `first + i`；
  显式数组逐项有界读取，不在 `take(limit)` 或预算生效前物化。
  类型标记与 count 范围须明确检查，不截断合法权重、长度或 ID。
- trie 构建完毕后仅在构建期重排为 BFS，保留每个节点的原边顺序。
  全局第 `i` 条边的 child ID 为 `i + 1`，无需逐边保存 child 整数。
  每节点 child 起点列有尾哨兵，words 引用分列。
  音节通过小型共享表定位，实际 414 种音节使用 u16 label；
  合法大 fixture 超过该范围时用显式更宽 label 格式或拒绝超出原 u32
  物理格式上限，不把音节/词条静默截掉。
- `Words`/`Edges` 继续惰性正反序迭代与首字母分组。BFS ID 只属内部表示，
  不得改变路径探索、候选排名、overlay 插入、学习快照或预算消耗。
  runtime 不建立解压缓存、全表 HashMap 或索引，不读取外部词典文件。
  分组的二分探针只读取音节首字节，检查 label、字符串区间和非空，
  不为比较首字母构造完整字符串；真正消费边时仍验证完整 UTF-8。
  对损坏的未消费音节，不要求在分组探针阶段提前检测其余字节；
  消费时必须拒绝非法 UTF-8，任何阶段均不得越界或使用 unchecked/unsafe。

可在上述契约内选择描述符的具体偏移、整数列对齐和 byte/位图；
不得为体积收益放宽候选/路径/输入安全规则。

## 后台纠错专用种子

仅优化完整索引仍会在两个 PE 中重复携带它。源码确认后台仅通过
`Corrector::load -> SpellingIndex::new(&Lexicon::builtin())` 引入完整索引，
实际仅使用 reading/text/weight，不需要全拼、简拼及混拼的运行期表。

新增构建期生成的专用拼写种子，后台不再引用 `Lexicon::builtin`：

- 采用同一完整 entries，以全拼 key 顺序、bucket 内原顺序输出
  `reading<TAB>text<TAB>weight<LF>`。只应用 `SpellingIndex::new` 原有的
  汉字范围、字数、规范读音和含元音筛选；所有合格记录保留，不在构建期
  新增 top-k 截断。权重和顺序不变，动态词典入口继续保留。
- eligibility 和种子行编解码由 `build_support/spelling_seed.rs` 共享。
  首轮内嵌 zlib 候选已证明完整结构等价，但引入了后台解压、分配和扫描成本。
  正式候选将原始 UTF-8 种子用 `include_str!` 内嵌，编译期检查 UTF-8，
  runtime 检查精确长度/SHA并逐行流式建修复 trie，不构造完整 `Lexicon`
  或其查询索引。由 ZIP/Inno 压缩原数据，避免将已压缩字节再次交给容器；
  展开 EXE 较 zlib 种子大，但以实际下载包和初始化时延验收。
- `SpellingIndex::builtin()` 与原 `new(&Lexicon::builtin())` 使用同一 trie
  插入、排序、去重及每 terminal 保留四项算法，公开候选 API 不变。
  `Corrector::load` 仅替换这一个工厂入口，不改变模型、推理或候选放行规则。
- 种子只在原有 AI 后台初始化阶段使用；TSF 首键不引用此路径，
  完整输入索引仍直接随机访问。不得将后台种子扫描带回输入线程。
- 以实际 PE 检查证明设置程序不再携带完整索引，TSF 不额外携带拼写种子，
  不依赖外置数据、动态加载或新文件安全例外。

验证时按相同输入顺序对原入口和新入口生成完整 trie 指纹，覆盖所有 child、
terminal text/reading/score 及顺序，分次构建避免双份峰值内存。
另补小 fixture、坏压缩/长度/SHA/字段及原拼写回归。
对两工厂分别测后台索引构建时间，并交错比较核心首键/暖查询负载；
不把较小 EXE 或无模型测试当作真实模型质量证据。

首轮完整结构对照通过，原节点/词条指纹为
`e54a1fdde58a82447b5f7bc44919767410ae84ad95f0852100a852def264fc80`，
但含指纹与释放的初测约为参考 3.73 秒、种子 4.22 秒。
后台构建增加公共前缀游标：仅在构建器局部复用上一条 compact reading 的
已确定节点路径，按最长公共前缀回退后继续原 BTree 插入；对任意行顺序、
相同 key、前缀变短和再分叉均应生成同一节点 ID 和词条顺序。
游标复用缓冲区，不为每行新增临时 Vec，不改变 eligibility、校验或 top4。
以保留在测试中的原 root-walk 构建器小 fixture 作为独立 oracle，
并核对完整指纹仍等于上述已测值，确认算法等价后重新计时。

## 验证与交付

构建时对完整索引逐 entry、key bucket、BFS 映射后的全部边及终端
与原构建对象比较（含文本、reading、weight、everyday 和顺序）。
保留动态 TSV/overlay/学习 fixture 对照，以及大 bucket/fanout 小预算
实际读取计数。格式损坏和边界不能依赖 unchecked cast 或 unsafe。

保留 v1 固定负载探针，在同机交错运行新旧进程，比较初始化、真实首键、
小 overlay、暖查询和长输入按键 P95/最大值。两者均为进程首次初始化，
不冒称清空物理磁盘缓存。测量若显示实质退化，继续调整而非宣称保性能。

体积先以索引/PE 的实际压缩数据定位收益，再以完整新 ZIP、安装器证明。
安装器压缩实验只对同一已校验载荷改参数，记录压缩耗时和解压字典内存估计；
不得用安装阶段压缩参数名或展开体积冒充最终下载收益。
新版本另名构建，保留 0.5.7 对照及其摘要。验收后交付新包，
不自动安装或更改用户输入法注册。
