# Flower Windows x64 分发与使用

Flower 支持 Windows 10/11 x64。当前源码版本为 0.4.23，提供离线 EXE 测试安装器与
ZIP 包；测试包尚未签名，校验哈希不等于验证发布者身份。不支持 x86 或 ARM64 宿主。

## 安装、启用与升级

1. 校验下载文件旁的 `.sha256`。例如：
   ```powershell
    Get-FileHash .\flower-0.4.23-windows-x64-setup.exe -Algorithm SHA256
   ```
2. EXE 安装器请求管理员权限，仅进行机器级安装与注册，不更改默认输入法。
3. 在普通用户桌面从开始菜单运行“启动 Flower”，再按 `Win + Space`
   选择 Flower。提升账户不是目标普通用户，安装成功也不等于已经切换输入法。
4. 保存设置、修改词典或学习开关后，重新切换到 Flower 才会载入新快照。

完成页默认勾选“启动 Flower”，点击完成后以原始普通用户身份启用 Flower 配置，
成功后退出，不打开设置窗口、不自动创建默认配置；可取消勾选。
注册或安装失败不启动，启动失败明确报错，不修改默认输入法。
“启动”不代表已切换当前焦点，仍可用 `Win + Space` 手动选择 Flower。

0.4.14在该选项下面增加“开机自启动”，默认不勾选，只作用于当前普通用户。
勾选后添加本安装的当前用户登录项；登录时静默启用后退出，不打开设置、
不弹窗口、不登录即加载模型、不改系统默认输入法。两个完成页选项互相独立。
可从普通用户开始菜单“Flower → 关闭开机自启动”取消。
未知或其他安装占用的同名启动项不会被覆盖或删除；提升令牌被拒绝。

安装器保守拒绝已有 Flower 注册，不支持原地自动升级。请先在使用 Flower 的用户下
停用，保存工作并正常退出加载旧 DLL 的应用，再通过旧版卸载器卸载；手工注册的版本
须从旧稳定目录用管理员终端运行 `flower-register unregister`。
启用过开机自启动的每个用户，请先从自己的普通权限开始菜单关闭自启动，再停用。
机器级提升卸载不代其他账户操作HKCU；未关闭的登录项可能留下失效引用。
不要覆盖正在使用的 DLL，不要删除未知注册表项、其他输入法或用户文件。
卸载失败或提示占用时保留现场，不强制关闭应用或删除安装树。

### 固定安装位置

按用户选择，0.4.3 起**取消自定义目录页**，固定安装到系统 Program Files 下的
Flower 目录（通常 `C:\Program Files\Flower`）。DLL、两个程序、词库、说明、
许可和卸载器在同一根目录及其版本子目录，`/DIR` 不允许改到其他位置。
使用 Windows 已知文件夹路径，不把字面 C 盘当作所有机器的固定事实。

已核对 anywork 提交 `b8c7b9ca07412ba1703fd58b6e01fea5a5fdc760` 的 Inno 脚本：
它是 `PrivilegesRequired=lowest` 的当前用户普通应用，默认
`{localappdata}\Programs\anywork`，文件放 `{app}`，完成页 `postinstall` 默认勾选启动。
Flower 的机器级 TSF 注册不能仅改目录就等价为该模型；本轮保留机器注册，
不实施未经证实的用户级输入法安装，也不再尝试修改已有父目录权限。
旧 0.4.1 用户副本或未知残留不由本版递归清理。Windows 注册表、快捷方式、用户词典
仍属于正常系统集成数据，不保证所有文件都只在程序目录。

注册工具提供两个不同入口：

```powershell
flower-register check-install-path --path "C:\Program Files\Flower"
flower-register prepare-install-path --path "C:\Program Files\Flower"
```

前者只读；后者会新建缺失目录，供管理员安装流程调用，不修复已有目录。
检查失败没有复制载荷或注册的授权；准备失败可能留下本次创建的空安全目录。
辅助命令保留旧路径检查能力，不代表本版 EXE 允许自选目录。
0.4.1 用户副本辅助命令仅保留兼容，新安装器不调用。

### ZIP 手工安装

ZIP 本身不提权。校验外部哈希和包内 `SHA256SUMS` 后，将文件放入受保护的稳定安装
目录，不从 Downloads、开发 `target` 或会话临时目录注册。
在管理员终端使用该稳定目录中的注册工具：

```powershell
.\flower-register.exe check-install-path --path "C:\Program Files\Flower\manual"
.\flower-register.exe register --dll "C:\Program Files\Flower\manual\flower.dll"
```

之后每个目标普通用户分别运行 `enable`。`disable` 只停用当前用户；机器级
`unregister` 不自动关闭应用，不删除 DLL、设置或其他用户配置。

## 输入和候选

### 内置离线 AI 纠错（实验功能）

0.4.18支持“一个词误拼＋另一个完整词”的组合建议，例如
`jintainzaoshang`、`jintianzaosahng` 可选择“今天早上 ✓ 拼写”，
不需要把每个组合句子预先加进词库。独立辅音单字母按词频合并单字读音，
避免低频独立读音把常用首字母候选挡到后页；保留原候选和`l`的“了、来”。

普通选词继续每次只前移一位，同一拼音重复选择可逐步靠前。
“兼容未声明范围的应用”现在同时用于普通排序学习和AI，独立于AI总开关；
微信等缺少范围声明的自定义输入框可进入同样的焦点、窗口和非密码检查。
兼容默认开启、已保存的关闭选择保留；关闭兼容恢复严格路径。
明确密码/PIN/私密、异常接口或不符合窗口检查的情况仍不学习，
未声明且没有标准密码标记的自定义敏感框可能无法识别。
修改设置后切换输入法生效；仍需开启本地选词记忆，不保证所有异常宿主都能学习。

建议来自本地词典，与模型验证的“✓ AI”分别标识；关闭AI不影响词典建议。
已有合法整词、同音异义、简拼和多处错误可能无法确定原意，不能保证任意误输入全部还原。
固定219条纠错测试集保留，新增20条组合误拼/正确控制，逐项结果单独提供，
包含失败与控制用例，不把可达率当成自动纠正率。

`flower-0.4.23-windows-x64-setup.exe` 或 `flower-0.4.23-windows-x64.zip`。
包中固定附带约115 MB的模型、运行库和说明，不再另生成普通轻量版。
升级仍需先安全卸载旧版，不要覆盖正在使用的DLL；旧版归档保持不变。

新用户默认开启“离线 AI 纠错”，与本地选词记忆开关独立，可以关闭。
旧配置中明确保存的关闭值仍会保留；旧版未见建议时请先确认该开关，
修改并保存后重新切换到Flower生效。模型缺失、校验失败或推理未就绪时，
继续使用原有词库输入，不回退到联网服务，也不在后台下载组件。
开启步骤：开始菜单打开“Flower 设置”，确认标题版本为0.4.23；
勾选“离线 AI 纠错”，点击保存，
再用Win+Space切走并切回Flower。设置版本仅代表设置程序，不单独证明宿主已换用新DLL。
已交付0.4.15包曾在候选窗状态前显示DLL版本；0.4.16按用户要求取消此前缀，
只保留AI状态和S编号。版本核对留在设置与独立诊断，不让版本文字常驻输入框；
设置窗口版本仍不能单独证明宿主已换用新DLL。不直接覆盖已加载DLL或强行关闭用户进程。

本版采用保守阈值，漏报较多，不承诺普遍修正所有错字，更不是自动语法润色。

### 常规输入

- 中文模式使用中文标点：逗号、句号、问号、感叹号、分号、冒号为 `，。？！；：`，
  括号为 `（）【】《》`，斜线为 `、`，Shift+6为 `……`，Shift+减号为 `——`。
  双引号交替 `“”`，空闲单引号交替 `‘’`；组词中的单引号仍为拼音分音符。
  组词时按标点确认完整当前候选后追加标点，不能完整消费时保留剩余原拼音。
  英文模式与Ctrl/Alt/Win快捷键保持直通，原减号/等号翻页仍保留。

- 全拼：`nihao → 你好`、`zhongguo → 中国`。`ü` 使用 `v`，如 `lv`、`nv`。
- 分音：`xi'an` 明确按 `xi + an` 查找；开头的普通引号不被当作组词吞掉。
- 简拼：整词每音节首字母，如 `nh → 你好`、`zg → 中国`、`xx → 学习`。
  0.4.15起仅输入一个字母也有单字补全：`l` 默认首页含“了、来、里、两、老”等；
  完整单音节候选仍优先，选择后保留完整规范读音，不把单字简拼边加入长输入词图。
  `zh/ch/sh` 都取其第一个字母 `z/c/s`；不是双拼，不会将未输入首字母的音节自动补齐。
  完整全拼优先，其后是整词简拼、整词混拼、组合和部分候选。
  日常词语使用项目维护的优先层，其内继续按原词频稳定排列；该层不是统计词频。
- 混合：每音节可输入完整拼音或首字母，例如 `shenmeys` 对应
  `shen'me'yi'si`，可从真实“什么”和“意思”组合为“什么意思”。
  内部保留完整规范读音，单行分页与本地前移同样适用。
  0.4.14增加独立有界混拼补充路径，原全拼路径保留，不用整句特例：
  `zheshism → 这是什么`、`womensr → 我们输入`、`weixinxx → 微信消息`。
  歧义输入不保证第一项，允许翻页选择；任意省略字母不等于合法逐音节混拼。
- `Space`、数字或鼠标选择候选。部分选词后保留同一预编辑，显示已确认中文及剩余拼音；
  全部选完才一次提交。
- 候选高亮在当前页首项时，`Left` 逐字符左移未确认拼音的光标；可连续移动到起点。
  `Right` 先右移光标，到达末尾的这一按不改变候选，再按才继续向后选词。
  高亮其他候选时的左移、上下键及翻页继续支持；上下或翻页会恢复光标到拼音末尾。
- 字母在光标处插入；`Backspace` 删除前一字符，`Delete` 删除当前字符。
  拼音起点退格会恢复上一段已选词的原拼音并保留后缀，本次不额外删字。
  光标在拼音内部时暂停AI建议，回到末尾停顿后恢复。
- `+`（主键盘 `=` 也可）下一页，`-` 上一页；支持数字小键盘加减，
  保留 PageUp/PageDown。非组词和 Ctrl/Alt/Win 快捷键直通。
- `Escape` 取消整段未提交内容。`Enter` 确认高亮完整候选；没有完整候选时提交
  已确认中文与原始剩余拼音，不静默丢弃后缀。
- 单独按下并松开 `Shift` 切换中英文。中文组词中会将整个未提交片段按原始拼音上屏，
  包括已经分段选择但尚未最终提交的中文；已提交文字不变，不记录本次选择学习。
  英文模式键入直通，再按 Shift 恢复中文；Shift 组合键和长按重复不切换。
  模式仅在当前激活会话生效，不修改系统默认输入法或持久设置。

输入长度上限为 128 ASCII 字节；超过上限拒绝本次修改，不截断已有输入。
离线组句使用有界静态词图，不是云端语言模型，也不保证每句话自动选对。

候选窗仅显示编号和候选文字，短候选紧凑单行，长中文候选按实际字体换行完整展示，

高亮按当前字体测量，文字末尾保留少量留白，背景为抗锯齿圆角矩形，不超出当前项；
整项仍可点击。窗口宽度有上限，

## 用户词典与设置

无参数运行 `flower-settings` 打开窗口，可调整候选页大小、主题、专业词库和学习开关。
用户词典位于 `%LOCALAPPDATA%\Flower\dictionary.json`，不写入安装目录。
导入、导出目前使用命令行；设置窗口的专业词库下拉框和“启用选中专业词库”
用于启停已导入的词库，不是导入按钮。无需管理员权限，也不需要重新安装。

### 准备词条文件

词条 TSV 为 UTF-8 三列：规范分音拼音、文字、正整数权重；一字一音节，例如：

```text
ni'hao	你好	1000
```

列之间必须是真正的 Tab，不是空格，也不是两个字符`\t`；不要添加表头。
拼音小写、去声调、用英文单引号分音，`ü`写作`v`。权重影响候选排序，但不保证置顶，
已有个人选词顺序仍优先。搜狗`.scel`、其他输入法专用格式和普通散文不能直接导入，
需要先转换成上述格式，不要只改扩展名。

在PowerShell中可生成一个UTF-8无BOM示例（`$words`应指向尚不存在的新文件）：

```powershell
$words = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'flower-words.tsv'
if (Test-Path -LiteralPath $words) { throw '示例文件已存在，请换一个文件名' }
$rows = @("qing'xu'jia'zhi`t情绪价值`t1000", "da'zi`t搭子`t1000")
[IO.File]::WriteAllText($words, ($rows -join "`n") + "`n", [Text.UTF8Encoding]::new($false))
```

### 导入、导出个人词条

找到`flower-settings.exe`所在的实际安装版本文件夹，在该文件夹打开PowerShell。
可从“Flower 设置”开始菜单快捷方式的属性查看目标位置；程序没有默认加入PATH，
所以下面使用`.\flower-settings.exe`，不要假定它在Program Files根目录。
文件路径可替换为自己的TSV，包含空格时保留引号。

```powershell
$words = Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'flower-words.tsv'
.\flower-settings.exe dictionary status
.\flower-settings.exe dictionary import "$words"
.\flower-settings.exe dictionary export "$env:USERPROFILE\Documents\words-export.tsv"
.\flower-settings.exe dictionary remove "qing'xu'jia'zhi" "情绪价值"
```

不带`--domain`导入的是始终参与查词的手工个人词条；重复导入按相同拼音与文字合并，
新文件中的权重替换该手工词对的旧值，不替换整份词典。
不带`--domain`导出的是当前可用的用户词库快照：手工个人词条、自动记忆词及已启用专业词库，
同拼音与文字保留最高权重；不包含内置词库、停用专业词库、启停状态或排序历史。
重新作为个人词条导入会合并成手工词条，不会恢复原来的专业分组或学习历史，
因此TSV导出不等于整份用户数据备份；需要分别保留某个专业库时使用下面的`--domain`导出。

### 导入专业词库并按需启用

专业词库与个人词条使用相同TSV格式。以下假定已准备好`terms.tsv`：

```powershell
.\flower-settings.exe dictionary import "$env:USERPROFILE\Documents\terms.tsv" --domain "专业词"
.\flower-settings.exe dictionary domain "专业词" on
.\flower-settings.exe dictionary domain "专业词" off
.\flower-settings.exe dictionary export "$env:USERPROFILE\Documents\terms-export.tsv" --domain "专业词"
```

新专业词库默认停用；同名再次导入合并词条，并保留其原启停状态。
也可打开“Flower 设置”，在专业词库下拉框选中“专业词”，勾选或取消
“启用选中专业词库（立即保存）”。停用不删除数据，之后仍可导出或重新启用。
命令完成或修改启停后，用`Win + Space`切走再切回Flower以载入新快照。

### 本地记忆与其他命令

```powershell
.\flower-settings.exe dictionary learning on
.\flower-settings.exe dictionary learning off
.\flower-settings.exe dictionary clear-learning
.\flower-settings.exe unicode U+20BB7
```

导入错行整体拒绝；专业词库新导入默认停用，必须明确启用。导出使用新文件，不覆盖
已有文件。坏 JSON、未知版本或超限文件报错并保留，不静默重建。可选专名 TSV 可通过
`--domain` 导入。已启用的规范词条也参与简拼。

0.4.2 的选词顺序记忆默认开启，**仅保存在本机**，无遥测、无云同步。成功提交的完整
候选在该次拼音/简拼候选组中仅前移一位：第二项下次变第一项，第五项只变第四项。
第一项保持不动，不再使用一次增加512权重来代替该行为。全拼和简拼分别记忆；
部分选择本身不记录排序；试探、取消、失败、失焦、密码、私密及未通过范围/原生组合验证的输入不记录。

0.4.19增加完整逐段组词的本地记忆：例如词库没有“新加卷”，一次输入`xinjiajuan`，
逐字选择“新、加、卷”，成功完整提交后自动记为词条，下次全拼`xinjiajuan`、
简拼`xjj`或混拼`xinjiaj`即可选择；至少两段明确普通选择，字数为2–32字。
读音取所选候选的完整拼音，不猜测未转换的raw，不从聊天或已提交正文提取。
取消、未完成、原拼、一次整句选择、AI及“✓ 拼写”建议不造词。
同次激活的新输入和空闲新上下文立即可用；成功保存后重启仍可用。
自动词独立索引，不在每次输入时扫描磁盘或重建大词库；最多保留4096条最近自动词。
支持自动词独立查词，不承诺其已作为任意长句的内部组合边。

同版候选窗在同屏更新时保持可见，只在必要时调整一次位置/尺寸，减少反复隐藏/显示造成的闪烁。
真正失焦、UIless拒显及错误时仍隐藏；跨屏DPI迁移保留必要隐藏流程。
隔离窗口消息验证不等于所有真实显示器、DWM或软件的视觉验收。

0.4.12为搜索、中文、聊天和文件名等普通类型统一学习发布规则，数字、鼠标、
方向加Enter/空格都使用同一成功提交链。同一激活的新上下文也读取已更新顺序，
后台成功保存后，重启应用仍保留；AI建议不进入这套普通选词记忆。
默认日常词从无限优先改为有界使用分数，不改源词频：保留“你好”，同时
“研究”仍排在低频“邮件”前，“世纪”排在“睡觉”前；个人已保存顺序优先于默认排序。

同一激活内的下一次新输入立即使用新顺序，已有正在组词的列表不偷偷换位。
后台保存失败不撤销文档提交，但会报告本地数据错误；不能把入队成功当作已写盘。
设置窗口或 `dictionary learning off` 可关闭，停止新增排序和自动词，已有自动词仍可查；
清空学习同时清除旧计数、顺序和自动记忆词，不删除手工个人/专业词条、不自动关闭开关。
修改开关或清空后重新切换输入法生效。
旧schema1/2文件只读迁移，不在load时重写；下一次合法更新保存schema3，保留已有开关与数据，
不从旧计数生成自动词。旧频次字段仍保留，但不再作为本版TSF的加权排序。
旧程序不识别schema3，降级前请备份数据。
词典文件按跨进程锁内重读、同步临时文件、原子替换持久化；不承诺进程崩溃前尚未处理
的队列事件都已保存。外部占用可能导致明确失败，不能靠删旧文件或放宽权限绕过。
Unicode 入口仅向标准输出打印一个合法非控制字符，无换行，不向应用注入或写剪贴板。

python -m unittest scripts.test_package scripts.test_installer

可以用 `--output-dir` 指定新的输出目录、`--iscc` 指定 Inno 编译器。
组包使用 `--locked`、真实 release Cargo artifact，检查 AMD64 PE32+、DLL 导出、
数据及许可，再生成单顶层 ZIP、`manifest.json`、`SHA256SUMS` 和外部 `.sha256`。
已有同名输出拒绝覆盖。安装器验证源 ZIP 后包装，另生成源 ZIP 哈希关联清单、
`.exe.sha256` 和 Inno 引擎许可；构建工具不会运行生成的安装器。

ZIP 包括 DLL、两个管理程序、本文、程序和依赖许可、单字/词组数据、来源清单及覆盖
报告。完整上游大快照保留在源码，不全部随运行包发布。包内多个 `manifest.json`
分属不同数据集；包身份应读取顶层 manifest，不能任选同名文件。

## 许可和验收边界

0.4.23 候选窗右侧使用齿轮图标打开设置，不再显示“设置”文字按钮。

组词中保留原拼音和已确认片段，不自动提交；不改变英文模式。
该快捷键不写磁盘，重新激活按设置页保存的默认字形载入。
若希望长期默认繁体，请在设置页选择并保存。

组词中先按原规则提交候选，再追加符号，不把 Shift 数字误作选词编号。
