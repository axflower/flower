# Flower 0.4.15 拼音纠错差异诊断

本页及修订3脚本精确匹配已交付0.4.15的固定helper；旧修订2只适用于0.4.12。
不要修改摘要或IPC版本强行运行。它不需要重新安装Flower，也不是纠错修复包。

用户反馈微信已可输入，但固定正例仍显示无建议。隔离TSF与包内真实模型组合通过，
不能代替发生问题机器的证据。工具用于区分实际后台/资产身份与固定句推理耗时，
不会抓取宿主实际输入，也不能仅凭其通过就称真实微信链路已经修复。

当前诊断工具为修订3，报告含 `diagnostic_revision: 3`、
`host_requests_captured: false` 和 `fixed_fixture_metadata: true`。
测试句的首候选文字及reading已同步0.4.15内置词库；核对helper摘要后才允许启动。
修订3同时只读枚举记事本及微信加载的Flower模块路径与磁盘摘要，不读窗口标题或正文。

修订2曾
修复了Windows PowerShell 5.1对注册路径 `\\?\C:\…` 调用 `Split-Path` 时
“drive为空”的错误；只转换本地盘符路径的提供程序表示，IPC仍使用实际canonical路径。
旧工具出现此错误且 `requests` 为空时，没有完成后台测试，不能据此判断模型结果。

1. 在发生问题的那台电脑上，将诊断ZIP完整解压到一个可写文件夹，保留文件在一起。
2. 保留测试微信/记事本打开，暂时停止输入，用普通权限双击 `diagnose-ai-pinyin.cmd`。
3. 等待完成，将同目录新生成的 `flower-ai-diagnosis-*.json` 报告交回分析。
   如果窗口报错且没有报告，保留窗口中的错误信息。

脚本从Flower的64位机器注册读取实际DLL位置，再定位同目录helper；
核对helper必须精确匹配已交付0.4.15。手工ZIP没有注册时可显式指定：

```powershell
.\diagnose-ai-pinyin.ps1 -Helper "完整解压目录\flower-settings.exe"
```

诊断仅发送七组写在脚本中的公开测试句：替换、交换、多字、漏字、两个正确句和旧CSC。
报告包含这些固定请求/响应、耗时、CPU型号、Flower注册路径、
记事本/微信加载的Flower模块路径及磁盘文件摘要。磁盘摘要不等于已加载映像的内存身份。
脚本不查询窗口标题、正文或用户词典，不修改注册、输入法设置或已有报告。
仅在没有后台时启动自己的helper，结束时回收自己持有的进程；既有后台保持运行。
启动器只对本次PowerShell进程使用执行策略参数，不修改系统执行策略。

解释结果时分清：

- 后台三类也返回空：继续分析该机器的后台、模型门禁或耗时差异。
- 后台四类均返回正确建议：继续核对记事本实际请求与发布链路。
- 摘要不符、连接失败、超时：先处理报告中的具体阶段，不能按“模型无建议”解释。
- 固定拼音正例返回空且耗时接近内部3秒预算：这是预算耗尽的线索，不直接等同已证明根因，
  应进一步区分生成、结构筛选、模型阈值与墙钟预算，不为演示降低门槛或硬编码“选→现”。

脚本独立于安装器，不需要重新安装Flower。运行前暂停输入，以免固定句诊断与正常请求
竞争后台服务；是否首次冷加载会影响耗时，报告本身不保证冷启动测量。
