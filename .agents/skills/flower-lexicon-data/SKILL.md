# Flower 词库数据流程

## 独立词库权威边界

公开词表、来源许可、覆盖、生成器及其测试由独立的 `flower-dict` crate/repository维护；本技能下方 `data/pinyin/`、`scripts/build_lexicon.py`、`build_phrases.py`、`build_categories.py` 与对应生成测试路径相对于词库仓库，不应在Flower重建第二份。Flower保留引擎、排序、TSF、用户数据和分发消费者，详见 `design/dictionary-crate-extraction.md`、`docs/dictionary-crate.md`。

当前分发目标为GitHub完整仓库，保留单crate与静态API，不以满足crates.io上传体积而删词或强制分包。Flower通过直接Git依赖消费，Cargo.lock须绑定实际提交；Python资产根由Cargo metadata根manifest身份及直接依赖package ID定位，支持rename，缺失/歧义/错误版本拒绝，不猜兄弟路径或扫描缓存。本地path或隔离验证副本不等于真实GitHub联调；远端更名、包名提交同步及真实来源校验完成后才报告接入成功。认证或远端404保留具体阻塞，不伪造lock、不读取/打印令牌、不自动改用户Git索引或擅自提交推送。Git源码包含重建原料，crate归档可仅带消费子集；原jieba频次校验仍需dict.txt与固定生成器，不能因移动来源而删门禁。完整许可按实际标准正文校验，新增合法变体先读全文再窄增可信摘要，标题或章节占位不得算完整许可。

静态数据crate不应依赖Flower候选类型、Windows、私有词典或AI模型。all/default表明确区分可选专名/MVP，原拼接字节与词对并集、人工prior的可选性分别核对。公开包只包含明确白名单，完整重建大原料留源码仓库；检查真实 `.crate` 而非仅Cargo清单，改文档或源后应重固定归档并比源码身份，publish dry-run不保证已保存 `.crate` 文件被更新。

先读当前 `design/adaptive-candidates.md`、`docs/distribution.md` 及 `data/pinyin/sources/manifest.json`，旧基础排序约定见 `design/input-and-installation.md`。历史设计若已不存在，不依据旧摘要恢复。以实际阶段和共享行为契约为准，不因数据量扩大就宣称整句输入或用户学习已实现。

## 来源与许可

- 引入数据前读取实际来源、完整许可及合并说明。仓库总体标 MIT 不代表它混合的所有数据都只有 MIT；不要盲目将 pinyin-data/pinyin.txt、Rime 字典或可下载的专有词库一并导入。
- 固定发布版本/提交、原始 URL、文件 SHA-256、归属和许可正文。来源探针先放当前 Thread scratch；确认交付的快照放 `data/pinyin/sources/`，不执行上游脚本。
- 当前单字流水线使用固定 Unicode Unihan 读音字段及独立的 8105 转录检查集。保留两者的许可和归属，不冒充官方字表认证。完整原始 Unicode 快照供源码重建，不要求全部进入运行包。
- 字节锁定的来源、生成 TSV 和覆盖报告必须保留 Git 属性，防止 Windows 换行转换破坏 SHA。来源更换时同步清单、报告、许可、包白名单和实际消费者。

## 转换与覆盖

- `scripts/build_lexicon.py` 是离线入口，无网络依赖。`--check` 必须只校验而不覆盖文件；不支持的记录、来源哈希不符或许可缺失时失败关闭。
- 有声调拼音去声调；处理 Unicode 分解的 ü 时先保留其区分，再转换为 v，不能直接删所有组合符号后把 ü 错当 u。单字多音字取实际来源，不为词组制造读音笛卡尔积。
- 去重单位是 `(拼音, 文字)`，保留最高权重。先按文字分组去重，再做候选权重排序；仅按权重排序后相邻 dedup 会漏掉隔开的重复文字。
- 报告唯一字符、拼音—字映射及基线覆盖，不能把多音映射行数当成字符数。基线要通过实际 `Lexicon::lookup` 证明可达，另验大候选集所有页面及末项提交。
- 扩展平面字符需验证 UTF-16 编辑/读回；不能凭一个生僻字看似有读音就假定所选来源收录它。缺字、缺读音和 Windows 缺字形是不同问题，不编造映射来使测试通过。

## 引擎与性能

- 保留纯安全 Rust 边界；文件路径、网络和持久化策略不能进入引擎。内置词典进程内共享，session/router 快照不能深拷贝整部底表；自定义 TSV 不污染内置缓存。
- 初始化失败显式返回错误，不用空词典或退回演示库伪装成功。词库扩大不得暗中改变 Space/Enter、取消、候选票据或 TSF 编辑语义。
- 旧测试需要固定页数/短末页时使用明确的小 fixture，另保留生产大词库回归；不要放宽断言或截断真实候选来维持旧页数。
- `cargo run --release --example lexicon_probe` 是固定开发负载：冷加载、暖查询分位值、空 router 克隆。它不是桌面端到端按键时延，也不代表多宿主 RSS；按实际指标描述结果，不制造通用硬件保证。

## 分音、组合与本地学习

- 词级数据保留真实音节边界和独立许可；CC-CEDICT 派生数据及词频来源的归属不能被程序根许可证替代。默认核心与可选专名扩展分别验证数量、互斥和哈希，不自动启用扩展。
- 原始 ASCII 消耗范围不能从中文长度反推。显式分音符属于前一个消耗片段，逐一检查所有相关部分候选，避免选择后遗留前导引号。不要只验证第一个候选。
- 组合使用有限图搜索，精确单字候选仍完整。整数 log 近似需保留桶内频率，否则不同高频词可能仅因字典序倒排；不要为句子回归硬加整句词条。
- 学习事件不是持久化许可：试探、取消、无解原始输入、失败/过期编辑不得学习；只在成功提交及可靠非敏感 scope 下投递。未知 scope 失败关闭。关闭/清空要推进代次，防止其他宿主旧队列恢复记录。
- Windows 用户数据更新保持锁内重读、同步同目录临时文件和原子替换。慢持久化下短固定轮询可能饥饿，使用有界内核等待并验证总期限、跨进程与 abandoned 接管；不取消同步或吞掉失败。
- 不假定 share-delete 读取句柄一定允许目标被替换。合作读取与写入须协调；用受控短暂/永久占用、readonly 和原生 API 最小复现验证原子一致性。任何有限重试都保留旧文件，不删旧目标、不改权限、不换非原子兜底。
- DLL 内工作线程须 stop/join，并在 join 后才释放独立 DLL 存活计数；不要只依赖文本服务字段的默认析构次序。

## 字频与整词首字母

- 当前契约见 `design/input-and-installation.md`。单字使用固定 jieba 快照的精确文字频率，并在优先读音/其他基线读音/扩展读音三档内压缩排序；不要直接让文字总频率跨读音档，否则 `yi` 的“也”等次读音可能压过“一”。来源与许可损坏须失败关闭，coverage 和包校验同步；完整读音及分页候选不截断。
- 内置表不再叠加 MVP 演示权重，MVP 仅供小 fixture 和审计。已声明无解的测试输入可能因简拼获得真实候选（例如 `xyz`），用明确小词典测试无解契约，不删除候选或放宽断言。
- 简拼仅规范分音词条的每音节首个 ASCII 字母，至少两音节且每字一音节；预建共享索引，overlay/learning 后同步，按键不扫描全表。不猜连写演示词、不默认混拼或缩写组句。实际消耗用缩写 raw 长度，显示/学习保留 canonical reading。
- 0.4.1 增加用户已选择的项目日常词优先层，只分类真实既有规范词条，明确不是统计频率，不改 weight 也不造读音。分类、overlay、learning、initial 索引排序须同步；自定义 from_tsv fixture 仍按权重。优先层会影响高权重私词与日常词之间的顺序，更新测试时须保留私词可达、weight不变和快照隔离断言，不简单删除旧断言。
- 0.4.1 候选顺序为完整全拼→整词简拼→完整组合→部分前缀，防组合字串挤在真实简拼词之前。`nh/wm/sm/ky/zg/xx` 可用真实内置表检验常用词首屏，不给不存在的词补造读音。优先层与实际词频证据应分开报告，不冒充无偏质量基准。
- `tests/common_ranking.rs` 覆盖真实内置排序和简拼，`tests/pinyin_sentence.rs`、`tests/lexicon_quality.rs` 覆盖状态与快照一致性；原生 Context 回归可验证 NH 到“你好”的编辑路径，仍不证明实机激活。

## 0.4.2 精确选词顺序（当前）

- 用户明确选择默认本地持久保存。使用独立PromotionEvent/RankingOrder/RankingCandidate及共享engine::promote_order，成功完整选择只与直接前驱交换一次；不能以count*512、一次置顶或分词LearningEvent代替。第2项一次变第1，第5项仅变第4，首项不动；保存按输入作用域区分全拼/简拼，未知ID不造候选。
- schema2新adaptive_ranking_enabled默认true；schema1只读迁移不重写，旧count保留但TSF不再叠旧频次加权。管理开关和清空推进generation，清空同时清counts/rankings；有界队列在clone前限制事件规模，锁内重读最新顺序合并，跨进程不能用过时UI快照覆盖新状态。未知版本或坏文件保留。
- 选择时仅捕获完整候选快照，partial不记录未消耗后缀；只在安全成功且仍聚焦的TSF发布兑现，使用一次性claim防重复。激活内Arc排序供空会话下次输入同步，正在组词不暗改；试探/取消/失败/密码私密未知scope无内存或磁盘提升。保存失败不回滚已成功文档提交，不宣称入队等于耐久保存。
- tests/adaptive_input.rs用明确“影射/映射”第2位fixture→成功提交→真实Store写入→新Store及内置词典session重放，验证“映射”变首项。完整候选不遗漏分页与序号/Enter/鼠标索引需和单行width真实page_ranges一起测试；不得仅让popup少画几项。

## 0.4.3 混合输入与整次解码预算

- 当前混输契约见 `design/mixed-input-and-installation.md`。规范词条每音节可全拼或首字母，保留 canonical reading、真实 raw consumed 与 Promotion scope；不预生成 2^n 组合，不每键扫描整词表，overlay/learning 同步共享音节 trie。
- 组合边的 top4/beam8 是语义与性能边界。真实目标词被裁剪时先取证具体词边排名；可由根明确调整已存在日常词分类，不造整句词条、不随意扩大 beam 或伪改频率。全拼、整词首字母、整词混拼、完整组合、部分前缀分层保持。
- 混输遍历每起点一次收集所有 prefix 终端；一次 decode 共用最多16384状态展开，单查询最多4096，不可对每 prefix 重置预算。整词 mixed 复用起点0结果，输出收集也有界；exact/initial 不因 mixed 预算耗尽被截断。用实际计数测试跨起点预算，不只断言返回向量长度。
- release 固定 `lexicon_probe` 包含长密集输入，预算有界不等于时延可忽略。优化前后在未改负载下测量；图区只取少量边时不要先构建整批 Choice 再 take。延迟物化或有界取边必须保持原排名与完整整词候选，不以减少合法匹配隐瞒回退。

## 项目人工常用短语

- `data/pinyin/everyday_phrases.tsv` 是独立项目人工表，MIT、人工权重，不冒称上游语料统计或扩大CC-CEDICT core/proper数字。当前数量及字节锁定以同目录说明和打包可信常量为准；新增规范词对归日常层，重合项保留最高权重不累加。
- 扩人工表还会改变分类生成器的baseline：运行官方离线生成入口更新coverage/manifest、补充表去重及provenance，不能只改EVERYDAY_COUNT/HASH或放宽分类摘要校验。部分CEDICT补充词会因已在人工表而从派生表移出；按所有默认表的并集比较增减，确认没有丢失旧词对，区分人工新增数、相对旧默认净新增数与相对新baseline的分类增量。同步可信category manifest摘要与相应边界测试。
- 人工拼音不能只靠“音节合法、字数相等”证明对应正确；对地名谐音网络词、多音字和易错字另做独立词义读音核对。代表项须以规范reading和真实raw完整消费串全拼/简拼/混拼普通选择，排除AI/SP标记；扩词可能产生新的合法组合，使固定普通排名变化，先记录具体竞争词和数据原因再更新测量基线，不为守旧位次篡改词频。
- 修改人工表须同步说明、打包固定数量/hash及manifest record，TSV以 `.gitattributes -text` 锁定字节。所有上游base/core/proper保持不可变；builtin、initial、mixed索引一致，自定义fixture不污染。
- 包新增文件必须同步 `scripts/installer.py` 固定白名单与必需项，不只更新package生成器；不放宽任意路径。来源、MIT正文路径、独立数量/hash、SHA256SUMS和实际DLL嵌入均核验。
- 全部条目exact lookup和initial session翻页提交与代表项full-session提交是不同证据，不扩大表述。缩写与合法全拼碰撞如wan，保留全拼层并验证后续页的我爱你，不把可达冒称首屏。

## 分类词库与可靠读音补充

- `scripts/build_categories.py` 管理 `data/pinyin/categories/` 的离线生成和 `--check`；THUOCL原始快照及许可在 `data/pinyin/sources/thuocl/`，类别清单、数量及可信版本以manifest为准，不把多类重合行数相加。
- THUOCL只有词和类别DF，没有拼音。精确CEDICT词级读音优先；缺词级读音时，只能组合每字在base全部不同读音集合大小恰为1的词，不能用首选读音替代无歧义判定或做多音笛卡尔积。DF为零仍可以是合法收录，不把零频当坏行；坏数字不修后缀。不同语料DF不冒称统一词频，人工映射与原始DF分别保存。
- 词级补充不再用jieba词频存在性决定收录；低频/无频词的排名与默认加载另有明确契约。儿化仅保留来源明确的末尾r词对，不机械造儿字或er别名。每表/provenance/coverage须能区分来源支持、待补读音、默认lookup可达及真正提交。
- 运行包仅固定生成表/manifest/coverage/NOTICE和原路径必需许可，原语料、provenance/rejected留源码审计。打包与Inno都用精确白名单和必需项；运行验证须绑定代码可信manifest摘要，不能只信载荷重算的自签摘要及零统计。取合法音节前先验证base本体摘要，来源例外须明确，防任意字母串伪称拼音。
- 新数据会改变普通首项与AI生成候选，因此补真实品牌/儿化全拼、简拼、混拼提交及受影响模型正反例；固定性能负载测共享快照和冷/热成本。仅改旧测试的首项基线时记录数据原因，不把旧词库证明当作新词库证明。

## 大规模词目同步与自动注音

- “词目完整”与“全部可用拼音查询”分开取证。盘点实际词典及辅助运行候选，包括英文、混输、繁体、addon、emoji、符号映射值；符号候选须按整个字符串保留，不导入YAML键或结构说明。维护检查片段、错词负例、内部控制项及动态生成输出应明确排除范围，不能静默漏词或整表盲收。
- 仅同步词目文字时，不自动复制原始频次或排名；项目统一低权重须标明不是统计词频。自动注音仅在用户已允许时使用，固定维护依赖版本，区分既有整词读音、自动推导、非拼音文本及待补项；未知生僻字保留文字和缺音证据，不编造读音或做多音笛卡尔积。自动音节合法不等于词义读音正确。
- 可选专名表的独有读音不得经扩充生成器提升到默认层；用包含proper-only读音的正反fixture验证。Python与Rust对控制字符的拒绝边界应一致，例如Unicode Cc包含C1，不能只拒ASCII；emoji所需的ZWJ等格式字符不能混同控制字符删除。
- 大原料不进crate时，明确离线重建/check要求完整源码仓库，不能承诺解包归档即可重建。检查必须只读、不导入刷新专用依赖；用真实全量差集、旧表字节不变、默认词对并集、字典API与实际归档载荷一致性验收。
- 大规模静态表应实测真实crate压缩体积、解包编译及源码逐字节对应，不能仅凭Cargo白名单或本地package成功称为注册表已发布。新增数据权利未核定时不冒称全部MIT或公开再分发已获保证；用户偏好不能替代实际来源证据。

## 最小充分验证

- 数据/转换：`python -m unittest scripts.test_lexicon -v`，`python scripts/build_lexicon.py --check`。
